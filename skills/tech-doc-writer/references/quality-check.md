# 质量自检

## 检查清单

### Check 1：读者理解
- [ ] 如果读者第一次看到这个主题，他是否知道自己现在正在解决什么问题？
- [ ] 文档开头是否有目的说明和适用范围？

### Check 2：结构
- [ ] 每一节是否服务于主线？
- [ ] 是否有不服务于主线的"介绍一些相关知识"？
- [ ] 每一节是否回答了"读者为什么现在需要知道这个"？

### Check 3：依赖
- [ ] 是否出现"还没解释 X 就突然使用 X"的情况？
- [ ] 概念依赖关系是否合理？

### Check 4：机制
- [ ] 关键结论有没有解释为什么？
- [ ] 因果关系是否完整？（条件 → 机制 → 中间状态 → 结果）

### Check 5：证据
- [ ] 哪些是事实？哪些是推断？是否标注清楚？
- [ ] 结论是否有 log 或命令输出作为证据？

### Check 6：工程
- [ ] 代码、命令、配置是否具有实际可执行性？
- [ ] 命令是否附带参数说明？
- [ ] 命令是否有预期输出？

### Check 7：边界
- [ ] 是否遗漏关键限制条件？
- [ ] 是否标注了版本差异、环境差异、权限要求？

### Check 8：深度
- [ ] 是否只是罗列知识，而没有真正解释？
- [ ] 深度是否与读者需求匹配？（不是太浅也不是太深）

### Check 9：冗余
- [ ] 删除这一段以后，核心理解是否受到影响？如果没有，删除。
- [ ] 是否有空洞总结、模板化段落？

### Check 10：AI 味
- [ ] 是否出现空洞总结？
- [ ] 是否出现模板化段落？
- [ ] 是否出现过度编号？
- [ ] 是否出现泛泛而谈？
- [ ] 是否出现重复解释？
- [ ] 是否出现口语化/拟人化比喻（"饿死""长这样""觉得"）？（反模式 14）
- [ ] 是否"看似完整、实际没有重点"？

## 修改优先级

1. 事实错误（最严重，必须修）
2. 逻辑错误（必须修）
3. 理解障碍（必须修）
4. 工程不可执行（必须修）
5. 信息不完整（建议修）
6. 风格问题（可选修）

## 多轮自检流程

```
初稿 → Check 1-10 → 修改 → 复检 → 最终稿
```

如果复检中仍有不通过项，继续修改，直到全部通过。
