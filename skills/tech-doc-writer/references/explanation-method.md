# 解释方法

## 认知建立方法

### 心智模型建立

当介绍复杂系统时，优先帮助读者建立一个能在脑中运行的系统模型。回答：

1. 系统由什么组成？
2. 组件之间怎么连接？
3. 数据从哪里来？
4. 经过什么处理？
5. 最终到哪里去？

必要时进一步：
- 状态怎么变化？
- 控制权在哪里？
- 失败在哪里传播？

### 因果解释链条

不要只描述 A 导致 B。尽可能解释完整链条：

```
条件 → 内部机制 → 中间状态 → 结果
```

**参考文档示例**：
- 参考文档中"播放音频后 suspend 音频卡顿"的解释：从"CPU 停止工作"到"DMA 控制器仍在运行"到"缓冲区残留"到"硬件关闭"，完整解释了为什么会出现循环卡顿。
- 参考文档中"4G 模块兼容方案"的解释：从"编译时固定 RIL 库"到"不同模块需要不同 RIL 库"到"需要开机动态识别"，完整解释了为什么需要检测服务。

### 建立概念边界

当引入新概念时，先定义它的边界：
- 它是什么（定义）
- 它不是什么（排除误解）
- 它和什么类似（类比）
- 它和什么不同（区分）

## 七种解释策略

### 1. 对比法

**适用场景**：说明多个方案、工具、方法的差异

**方法**：列出各方案的核心差异，说明选择理由

**参考文档示例**：PulseAudio vs PipeWire 对比、GRUB vs EFISTUB 启动对比

### 2. 条件列举法

**适用场景**：同一个问题在不同条件下有不同解决方案

**方法**：按条件分类，逐一说明

**参考文档示例**：4G 模块的三种方案（PPP/ECM/QMI）、声卡问题的四种方法

### 3. 问题清单法

**适用场景**：多个不相关的问题汇总

**方法**：每个问题独立编号，内部结构一致

**参考文档示例**：M82A 反馈问题修复（NFC 调试、声卡调试、TP 手写笔）

### 4. 信号分类法

**适用场景**：从信号/数据流向解释系统

**方法**：追踪信号/数据从输入到输出的完整路径

**参考文档示例**：Intel Agentic AI SDK 中请求从 OpenClaw 到 Router 到 Guard 到 Policy 的完整流转

### 5. 平台对比法

**适用场景**：同一功能在不同平台上实现不同

**方法**：对每个平台独立完整描述，不交叉对比

**参考文档示例**：RK/QCOM/MTK TP 调试方法、x86 与 ARM 核心差异

### 6. 命令驱动法

**适用场景**：以排查命令为主线组织内容

**方法**：每个命令附带参数说明、预期输出、判断依据

**参考文档示例**：NFC 调试中的 i2cdetect、acpidump 命令链

### 7. 组件分类法

**适用场景**：系统由多个子系统组成

**方法**：按功能模块分类，每个模块独立说明

**参考文档示例**：Yocto 项目中的 metadata/layer/recipe/bitbake 分类
