# 图表选择

## 核心原则

如果简单几句话就能说清楚，不要画图。

文字表达关系会造成较高认知负担时，使用结构化视觉表达。

## 表达形式选择规则

| 关系 | 表达形式 | 说明 |
|------|----------|------|
| 组件关系 | 架构图 | 系统由哪些组件组成，如何连接 |
| 处理过程 | 流程图 | 步骤之间如何流转 |
| 顺序操作 | 编号步骤 | 简单的先后关系 |
| 数据传播 | 数据流图 | 数据如何产生、转换、消费 |
| 时间关系 | 时序图 | 交互顺序和时间关系 |
| 状态变化 | 状态机 | 状态如何切换 |
| 空间关系 | 示意图 | 物理布局 |
| 大量属性比较 | 表格 | 多维度对比 |
| 复杂因果 | 分层解释 | 因果链条 |
| 条件分支 | 决策树 | 多个条件分支 |
| 机制演示 | 代码 | 如何实现 |
| 最小实现 | 代码 | 快速参考 |

## 参考文档中的图表使用

- **LCD 框架文档**：使用流程图展示驱动加载流程（LK 阶段 → Kernel 阶段）
- **Intel Agentic AI SDK 文档**：使用 Mermaid 架构图展示组件拓扑结构
- **Gsensor 调试文档**：使用坐标系图展示物理方向
- **新人指导文档**：使用流程图展示标准适配流程（确认硬件 → 确认驱动 → 确认系统策略 → 回看 BIOS）
- **Yocto 项目文档**：使用流程图展示构建流程和 BitBake 工作流

## 不要画图的情况

- 一个列表就能说清楚
- 简单的一句话就能描述
- 关系只有 2-3 个节点
- 读者不需要理解整体结构，只需要知道某个具体操作
